# 🔬 扫书（通用型） v2.4 (节点分层联动记忆版) 

本仓库为 **扫书 v2.4 纯成品绿色免安装分发仓**。无需安装 Python 环境，无需配置任何代码，下载解压即可直接在 Windows 系统上全功率全自动跑通小说风控与排雷。

---

## 🚀 极速上手三步走

1. **一键下载**：点击本页面右上角的绿色 `Code` 按钮 -> 选择 扫书（通用型） v2.4.exe`，将程序下载到本地。
2. **靶场装弹**：双击运行一次 `exe` 程序，软件会自动在同级目录下生成 `books`（小说放这里）和 `reports`（报告产出这里）两个文件夹。
3. **点火开扫**：把你想排雷的 `.txt` 小说丢进 `books`，在界面上填入你的 API Key，点击“验证节点”并选好模型，最后猛戳 **【一键启动显微镜扫书管线】** 即可！

---

## ⚡ 核心黑科技优势

* **🛡️ 异步线程守护**：联网鉴权、握手、DNS 解析全部在后台独立子线程运行，配合 `httpx` 5秒暴力网络熔断，**没开代理、网络卡死也绝对不会白屏无响应**。
* **🔄 SQLite 断点自愈接力**：中途没钱了、中转站断连、或者 Gemini 圣母病发作拒答？**换线/充值后重新启动，0秒秒跳过已完成分块，原位精准接力续扫**，绝不浪费一分钱 API 额度！
* **⚡ 节点分层级联记忆**：自动记住你的 Key 属于哪个平台，切换接口地址自动过滤，多账号历史从此整整齐齐。

## 🤖 核心模型推荐与 API 兼容性圣经

本主程序基于标准的 OpenAI 协议（Chat Completions API）打造，只要你的接口地址（Base URL）支持该标准，理论上可兼容全网 99% 的大模型。但在“小说长文本、复杂 SOP 规训”的极端排雷场景下，各家模型在软件外壳中的真实运行表现存在物理客观差异。

以下为全网主流大模型在 v2.4 软件外壳下的**流畅度、兼容深度与避坑排查指南**：

#### 2. Anthropic Claude 系列 (`claude-3-5-sonnet`, `claude-3-5-haiku`)

#### 3. Google Gemini 系列 (`gemini-3.5-flash` / `gemini-3.5-pro`) —— 极速代步车，但自带“圣母风控”
* **兼容填法**：`gemini-3.5-flash` 或 `gemini-3.5-pro`
* **接口地址格式**：官方直连必须完整填写为 `https://generativelanguage.googleapis.com/v1beta/openai/`
* **实战体验**：
  * **外壳流畅度**：★★★★☆（前中期极速，后期依赖网络）
  * **协议兼容度**：★★★★☆（官方 OpenAI 兼容层，但有参数阉割）
* **会否报错崩溃（🚨 重点排雷指南）**：
  在跑 Gemini 官方接口时，一定会遇到以下两个 v2.4 外壳已经完美兼容、但必须知晓的底层物理现象：
  
  1. **“两分钟死等”现象**：如果直连国外官方节点，**却忘记开启本地代理（梯子）**。点击【🔄 验证节点并获取模型】时，Windows 系统内核网络栈会因为域名无法解析而强行死等重试。这期间**由于 v2.4 内置了后台异步线程守护，你的前台界面依然丝滑、绝不白屏卡死**。后台会在 1~2 分钟左右彻底熔断，此时请开启全局代理即可实现 0.1 秒秒过。
  
  2. **“分块后期 404 / 吐空值拦截”现象**：这是 Gemini 扫书时的头号大坑！
     * *死因一*：随着小说越扫越往后，你的历史前情记忆摘要会越攒越多。一旦【前情摘要 + 当前生肉分块】的总长度触发了中转站或官方网关的某项限制，Gemini 的兼容层不会返回标准的超长错误，而是直接无情甩给你一个 **`Error code: 404 - bad_response_status_code`**！
     * *死因二*：Gemini 拥有全球最严厉的“圣母型内容风控”。如果你的小说推到卷 3 左右，剧情迎来了两性擦边或大规模杀戮高潮，Gemini 会**瞬间拒答并吐出异常空值**。
  
  * **避坑绝招**：一旦黑框日志显示 Gemini 触发了 404 或空值拦截保护，**千万别关软件，利用 v2.4 强大的 SQLite 缓存机制，直接原地热切换成 `deepseek-chat` 或通义千问**，再次点击启动，管线会 0 秒跳过前面所有章节，在断点处完美接力续扫！

#### 4.  xAI Grok 系列 (`grok-4.3` / `grok-4.20`) —— 乐子人风控官，注意限流
* **兼容填法**：`grok-4.3` 或中转站对应的 Grok 别名
* **接口地址格式**：官方直连通常为 `https://api.x.ai/v1`（需常驻全局代理）
* **实战体验**：
  * **外壳流畅度**：★★★★☆（速度极快，但脾气暴躁）
  * **协议兼容度**：★★★★★（官方原生适配 OpenAI 协议）
* **会否报错崩溃**：
  1. **高频连续发包易触发 429 限流**：Grok 官方对单分钟发包频率（Rpm）限制极严。扫书这种长文本长对话场景下，如果分块切得太碎、推进太快，日志极易弹出 `429 Too Many Requests` 限流拦截。建议配合单线程模式慢速服用。
  2. **偶发格式不服从**：Grok 骨子里带有些许叛逆人设，在面对极其死板的表格输出要求时，它偶尔会因为“多嘴说骚话”而导致 Markdown 格式坍塌。外壳遇到此类乱码会**自动激活管线拦截机制**，保护你的历史数据不被污染。
  3. **尺度惊喜**：作为马斯克旗下的反大包揽风控模型，它和 DeepSeek 一样，**基本没有西方那种迂腐的圣母病**。遇到网文里的杀戮、黑暗流剧情绝对不会无故太监拒答，抓雷极其硬核！

| **国内官方** | `https://api.deepseek.com` | **必须关闭代理**（直连速度最快） | 如果开着代理点，可能会因代理回环导致验证卡顿。 |
